# 簡易設計書 — ネムの仕組みをざっくり理解する

むずかしい話ぬきで「どう動いてるのか」だけ分かる版。詳しくは [詳細設計書](architecture.md)。

## ネムは3つの部品でできている

| 部品 | 正体 | 場所 |
|---|---|---|
| **顔（画面）** | AITuberKitというOSSを改造したWebアプリ | ブラウザの `localhost:3000` |
| **頭（人格と会話）** | Claude（AI）を裏で常駐させておく小さなサーバー「brain」 | `localhost:8100` |
| **声** | Irodori-TTSという音声合成。声はガチャで引いた専用ボイス | `localhost:8088` |

全部自分のPCの中で動く。外部サービスに会話は送られない（頭のClaudeはAnthropicに繋がるが、Claude Codeの契約枠内）。

## 話しかけると何が起きるか

1. 画面で送信すると、文章が brain に届く
2. brain の中で常駐している Claude が「ネムの人格設定」を読んだ状態で返事を作る
   - 返事には `[happy]` みたいな感情タグが必ず付くルールにしてある
3. 返事の文章が Irodori-TTS に送られ、感情タグに合わせた演技指示つきで音声になる
4. 音声が再生され、その**音量に合わせて口が動く**（音が大きいほど大きく開く）
5. 感情タグに合わせて目や表情も変わる

つまり「感情タグ」が全部の橋渡し役。文章・声の演技・表情がぜんぶこのタグで連動する。

## キャラが動く仕組み

- 元は**立ち絵1枚**。AIツール（see-through）で髪・顔・服などのレイヤーに分解
- 口5種・目6種の差分絵を合成して1つのPSDファイル（`nemu.psd`）にビルド
- Anime2.5DRigというツールがそのPSDを読んで、まばたき・呼吸・髪揺れ・口パクを自動で付けてくれる
- 「口や目の切替は必ず1枚だけ表示」方式にしてある（フェードで混ぜると線が透けて汚く見えるため）

## 会話の記憶

- **セッション管理**: ChatGPTみたいに会話を分けて保存・再開できる。切り替えると brain 側も自動で文脈を作り直す
- ただし今は「セッション内の記憶」だけ。**セッションをまたいでネムが覚えている機能（長期記憶）はこれからの宿題**

## データの置き場所

- 会話ログ・セッション: ブラウザの中（localStorage）
- 人格設定: `brain/persona.md`（ここを書き換えると性格が変わる）
- 声の設計: `docs/nemu-voice-design.md`
- キャラの絵: `assets/character/`

## 動かし方

READMEの起動コマンドで3つのサービスを立ち上げて `localhost:3000` を開くだけ。TTSだけ起動に40秒くらいかかる。

## 困ったとき

- **声が出ない** → TTS(8088)がまだ起動中かも。40秒待つ。ログは `_logs/irodori.log`
- **返事が来ない** → brain(8100)が落ちてないか確認。ログは `_logs/brain.log`
- **設定ボタンが消えた** → 画面左上の⚙が復帰ボタン
